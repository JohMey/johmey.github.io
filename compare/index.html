OneSimulation compared with multiphysics packages and FEM libraries

OneSimulation sits between graphical multiphysics packages such as COMSOL Multiphysics or Ansys and open-source finite-element libraries such as FEniCSx, Firedrake or scikit-fem. This page says what is different, feature by feature.

Coming from a graphical package

You keep ready-made physics, built-in CAD and meshing. What changes is the way you work: the whole study is a Python script, so a variant is a loop, a report is a function call and a review is a diff. The method is no longer fixed by the physics interface. One shock tube through every method shows how far that goes.

The Application Library covers the subject areas of a model gallery with 377 worked examples. Each states its reference and how close the result comes.

Coming from an open-source FEM library

You keep Python and full control over the numerics. What you gain is everything around the equation: physics modules with their material models and boundary conditions, CAD and meshing in the same package, finite volumes, finite differences and discontinuous Galerkin next to finite elements, and results, figures and export without glue code. When a module does not cover your case, define and solve your own equation.

Working with an AI assistant

The download includes a local MCP server. Codex and Claude Code use it to create, save and run studies on your machine and to read the results back. For everything else the assistant writes Python against the same API. Run a study from Codex or Claude Code.
